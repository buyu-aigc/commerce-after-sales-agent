# 电商售后 Agent

这是一个面向电商售后的客服 Agent。

- **客户能做的事**：用自然语言查订单，申请退款、取消或开票，撤回申请，问进度。
- **系统怎么处理**：先理解诉求，再按售后政策分流。符合规则的自动办理，其余转人工审核。审核和对话互不阻塞。

要解决的问题是：面对复杂请求时降低人工审核量。复杂请求包括一句话里有多个诉求、口语化的指代、中途改口、多轮补充等。

> 这是演示项目。订单来自 Olist 巴西电商公开数据集（金额单位 R$），售后政策是演示规则，退款、取消等都是模拟事件，不连接真实的支付或物流。

## 评测结果

**衡量口径**

- 人工处理量 = 策略下限 + 额外人工。策略下限是政策要求必须人工审核的部分；额外人工是 Agent 没处理好、只能转人工的部分。
- Agent 只对"额外人工"负责。放宽政策是另一条线，两边的数字不混在一起。

**评测集**

- 52 段客户对话、99 个计分诉求，覆盖复杂请求、订单指代、授权语义、多轮对话和安全试探。
- 账号里有 18 笔订单，自动办理、转人工审核、不受理的情况都有。同一类目的订单要靠金额、状态、日期来区分。
- 期望结果按业务规则确定，判定全部自动。
- 模型用 deepseek-flash，每个版本跑一遍。

| 指标 | 改进前的基线 | 改进版（每个写操作都确认） | 本版本（分级确认） |
| --- | --- | --- | --- |
| 诉求正确 | 87/99 | 97/99 | 95/99 |
| 整条办结（共 52 条） | 43/52 | 50/52 | 48/52 |
| 可自动的实际自动 | 10/12 | 12/12 | 12/12 |
| 人工介入（策略下限 26） | 33（多 7） | 27（多 1） | 28（多 2） |
| 错误执行 / 信息泄露 / 高风险误自动 | 0 / 0 / 0 | 0 / 0 / 0 | 0 / 0 / 0 |
| 客户点击 | 0 | 45 | 14 |
| token | 68.3 万 | 36.3 万 | 36.3 万 |

- 两个改进版本相差 2 个诉求，在单次运行的波动范围内（约 ±2 个诉求）。
- 评测数据、字段说明和逐条结果在 [evaluation/heldout/](evaluation/heldout/)。

## 核心设计

- **模型只负责理解。**
  - 先列出客户这一轮的每个诉求，再拆成任务。
  - 订单从客户名下的编号列表里选。认不出唯一一笔时，给出候选订单，让客户点选。
- **服务端负责校验。**
  - 校验订单是否属于客户、任务类型是否合法、写操作有没有客户原话作依据。
  - 某个任务格式有误时，只限制这一项，不会作废整轮。
- **分级确认。**
  - 会直接生效的自动取消、自动退款，以及撤回申请，要客户点击确认。
  - 本来就要人工审核的申请直接提交。
  - 是否"一定会送审"在提交前预判。预判和写操作路径用同一套决策引擎和策略守卫，拿不准的一律照常确认。
  - 动作对、订单错时，可以点"不是这笔"换一笔订单。
- **政策分流**（演示政策包，见 `policies/`）：
  - 待发货且金额低于 R$300 的取消，自动办理；
  - 已送达、晚到 10 天及以上且金额不超过 R$100 的退款，自动办理；
  - 金额 R$300 及以上、重复申请、退款失败，一律送审；
  - 其余情况默认送审。
- **审核和对话分开。**
  - 工单在独立的工作流里等待审核，客户可以继续对话、问进度。
  - 还没审核的申请可以撤回。撤回用原子的条件更新实现，撤回之后审核员不能再批准。

## 快速开始

需要 Python 3.11 及以上版本。

```bash
uv sync --extra dev
cp .env.example .env    # 把 OPENAI_API_KEY 换成你自己的 DeepSeek key
uv run uvicorn app.main:app --port 8000
```

- 客户页面：http://127.0.0.1:8000/customer
- 审核台：http://127.0.0.1:8000/review
- 不填 key 时以离线模式启动：页面能打开，但不会调用模型。

运行测试（608 项）：

```bash
uv run pytest -q --ignore=tests/e2e
```

## 已知问题与局限

- 改地址时，即使客户给了新地址，也提交不了。
- 消息里带了别人的订单号时，整条消息都会被拒，同一句里的正常请求也不会处理。
- 带条件的请求不会执行，比如"如果还没发货就取消"。
- 响应偏慢。deepseek-flash 会先推理再回答，每条回复的中位耗时约 8 秒。
- 评测方面：
  - 每个版本只跑了一遍；
  - 评测集只覆盖 4 个类目；
  - 政策是演示规则。
